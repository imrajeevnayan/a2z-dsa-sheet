 # 🚀 Sliding Window Pattern — Complete DSA Roadmap


 If you are preparing for **LeetCode, GeeksforGeeks, coding contests, or interviews**, Sliding Window is one of the most important DSA patterns to master.


 The goal is not to memorize 20–30 solutions.


 The goal is:


 > 🧠 **See a problem → identify the window → decide what state to maintain → expand/shrink correctly.**


---


 # 📌 1. What is Sliding Window?


 Sliding Window is a technique used mainly for problems involving:


 - 📦 Contiguous subarrays

- 🔤 Substrings

- 🔢 Consecutive elements

- 📏 Longest/shortest range

- 🧮 Maximum/minimum/count of valid ranges


 Instead of recalculating every subarray from scratch, we maintain information about the current window and move it efficiently.


 Example:


```

arr = [2, 1, 5, 1, 3, 2]

           ← window →

```


 We usually maintain two pointers:


```

l = left boundary

r = right boundary

```


 Window:


```

[l ........ r]

```


 The basic movement is:


```

➡️ Expand using r

⬅️ Shrink using l

```

 # 🧠 3. The 5 Questions You Must Ask


 Before coding, answer these:


 ### 1️⃣ What is my window?


 Example:


```

[l ... r]

```


 ### 2️⃣ What information do I maintain?


 Possible states:


 - Sum

- Frequency map

- Number of distinct elements

- Number of zeros

- Number of odd numbers

- Character frequencies

- Maximum/minimum using deque


 ### 3️⃣ When does the window become invalid?


 Example:


```

distinct > K

sum > target

frequency > allowed

```


 ### 4️⃣ How do I make it valid again?


 Usually:


```

while (invalid) {

    remove arr[l]

    l++

}

```


 ### 5️⃣ When do I update the answer?


 This depends on the problem:


```

Longest  → max(window length)

Shortest → min(window length)

Count    → add window length

```

 # 🟢 LEVEL 1 — Fixed Size Sliding Window


 This is the easiest form.


 The window size is already given:


```

window size = K

```


 So:


```

r - l + 1 = K

```


 ### 🔑 Pattern


```

➡️ Add arr[r]


If window size == K:

    update answer

    remove arr[l]

    l++

```


 ### 🧩 Template


```

int l = 0;

long long sum = 0;


for (int r = 0; r < n; r++) {


    sum += arr[r];


    if (r - l + 1 == k) {


        // update answer


        sum -= arr[l];

        l++;

    }

}

```

 # 🟡 LEVEL 2 — Variable Size Window


 Now the window size is NOT fixed.


 The condition determines how large the window can be.


 Example:


 > Find the longest subarray with sum ≤ K.


 We start expanding:


```

[2]

[2 1]

[2 1 3]

```


 Suppose condition becomes invalid:


```

sum > K

```


 Then shrink:


```

[2 1 3] ❌


remove 2


[1 3] ✅

```


---


 # 🔥 Variable Window Template


```

int l = 0;


for (int r = 0; r < n; r++) {


    // add arr[r]


    while (window is invalid) {


        // remove arr[l]

        l++;

    }


    // update answer

}

```


 Remember:


```

RIGHT → Explore / Expand 🚀

LEFT  → Repair / Shrink 🔧

```

 # 🔴 LEVEL 4 — Shortest Valid Window


 Now the thinking changes.


 Suppose the question asks:


 > Minimum length subarray whose sum is at least target.


 Here we don't wait until the window becomes invalid.


 Instead:


```

Window becomes valid

        ↓

Update minimum

        ↓

Try shrinking

        ↓

Can we make it even smaller?

```


 ### Template


```

for (int r = 0; r < n; r++) {


    add(arr[r]);


    while (window is valid) {


        ans = min(ans, r - l + 1);


        remove(arr[l]);

        l++;

    }

}

```


 ### 🧠 Golden Rule


 For **Longest**:


```

❌ Invalid → Shrink

✅ Valid   → Answer

```


 For **Shortest**:


```

✅ Valid   → Answer + Shrink

❌ Invalid → Expand

```

 # 🔵 LEVEL 5 — Frequency Map Sliding Window


 Now Sliding Window becomes much more powerful.


 Used heavily for strings.


 Example:


 > Longest substring with at most K distinct characters.


 Maintain:


```

unordered_map<char, int> freq;

```


 Example:


```

window = "aabac"

```


 Frequency:


```

a → 3

b → 1

c → 1

```


 Distinct count:


```

3

```


 If allowed K = 2:


```

3 > 2

```


 Window is invalid.


 Shrink from left.


---


 # 🔑 Frequency Window Template


```

unordered_map<char, int> freq;

int l = 0;


for (int r = 0; r < n; r++) {


    freq[s[r]]++;


    while (freq.size() > k) {


        freq[s[l]]--;


        if (freq[s[l]] == 0)

            freq.erase(s[l]);


        l++;

    }


    ans = max(ans, r - l + 1);

}

```

 # 🔥 LEVEL 7 — Exactly K Pattern


 This is one of the most important tricks in Sliding Window.


 Suppose:


 > Count subarrays with exactly K distinct integers.


 Instead of solving exactly K directly:


```

Exactly K

=

At Most K - At Most (K - 1)

```


 So:


```

exactly(3)

=

atMost(3) - atMost(2)

```


 🔥 This trick appears in many problems.

 # 🧠 LEVEL 8 — Counting Valid Subarrays


 This pattern is extremely important.


 Suppose current window is:


```

[l ........ r]

```


 and the window is valid.


 How many valid subarrays end at `r`?


 Answer:


```

r - l + 1

```


 Example:


```

[a b c d e]

  ↑       ↑

  l       r

```


 Valid subarrays ending at `r`:


```

[e]

[d e]

[c d e]

[b c d e]

[a b c d e]

```


 Total:


```

5 = r-l+1

```


 Therefore:


```

ans += r - l + 1;

```


 🔥 This one line solves a huge class of counting problems.

 # 🟠 LEVEL 9 — Character Replacement Pattern


 Classic problem:


 > Longest Repeating Character Replacement


 Example:


```

s = "AABABBA"

k = 1

```


 Window can contain multiple characters.


 We maintain:


```

window length

maximum frequency character

```


 Important formula:


```

characters to replace

=

window length - maxFrequency

```


 Window valid when:


```

windowLength - maxFrequency <= K

```


 This pattern teaches you that the window state doesn't always mean simply "number of distinct characters."

 # 🔴 LEVEL 10 — Minimum Window Substring


 One of the most important Sliding Window problems.


 Problem idea:


 > Find the smallest substring of `s` containing all characters of `t`.


 Example:


```

s = "ADOBECODEBANC"

t = "ABC"

```


 Answer:


```

"BANC"

```


 Pattern:


```

Expand

   ↓

Do we contain everything?

   ↓

YES

   ↓

Update answer

   ↓

Shrink aggressively

   ↓

Become invalid

   ↓

Expand again

```


 This is a **must-solve** problem.

 # 🔥 LEVEL 11 — Sliding Window + Deque


 Now we move into advanced territory.


 Question:


 > Find maximum element in every window of size K.


 A normal window isn't enough if you repeatedly scan the window.


 We use:


```

Deque

```


 Maintain indices in decreasing order.


 This gives:


```

O(n)

```


 instead of:


```

O(nK)

```


 ### 🎯 Must Solve


 1. Sliding Window Maximum

2. Sliding Window Minimum

3. First negative number in every window

4. Constrained Subsequence Sum

5. Shortest subarray with sum at least K

 # ⚠️ LEVEL 12 — When Sliding Window DOES NOT Work


 This is just as important as knowing when it works.


 Suppose:


```

arr = [2, -5, 10, -2]

```


 and you're dealing with a sum condition.


 With negative numbers:


```

Adding an element

```


 doesn't necessarily increase the sum.


 Removing an element doesn't necessarily decrease it.


 Therefore the normal sum-based Sliding Window assumption can break.


 ### 🚨 Warning Sign


 If you see:


```

negative numbers

+

exact sum

```


 consider:


```

Prefix Sum + HashMap

```


 instead.


 Example:


 > Count subarrays with sum exactly K.


 For arbitrary integers, a common solution is:


```

Prefix Sum + Frequency Map

```


 not standard Sliding Window.

 # 🧩 Sliding Window vs Other Patterns


 ## Sliding Window


 Use when:


```

Contiguous range

+

maintainable state

+

optimization/counting

```


---


 ## Two Pointers


 Usually:


```

left/right pointers

```


 but doesn't necessarily maintain a traditional window.


 Example:


```

Two Sum II

3Sum

Container With Most Water

```


---


 ## Prefix Sum


 Think:


```

Subarray sum

+

negative numbers

+

exact target

```


---


 ## Binary Search


 Think:


```

Minimum/maximum answer

+

monotonic feasibility

```


 Sometimes Sliding Window and Binary Search can both look tempting; identify which property is actually monotonic.


---


 ## Monotonic Stack


 Think:


```

Next greater

Next smaller

Previous greater

Previous smaller

Histogram

```
